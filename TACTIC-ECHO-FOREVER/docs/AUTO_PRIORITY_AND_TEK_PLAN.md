# 自动场景、动态优先级与TEK后续实施契约

当前已实现Research.lua的旁路原型与模拟验证，未开放自动切换或动态派发。此文件具体承接用户“先手动双练习，同时着手自动/动态”的授权。

## 自动场景

当前采样来源C_NamePlate.GetNamePlates，每次最多40个当前可见条目；字段、单位token、存在/可攻击/死亡返回分别检测，原始Frame、token和目标身份不保存。分类只表示可见、可攻击且存活单位数量，不表示实际技能命中敌人数。

原型阈值：≥3建议multi，≤1建议single，2保留当前。两个不同采样轮、间隔不超过1秒才产生建议；重复轮不确认，UNKNOWN、生命周期变化和过期清除确认。现在只有人工sample入口，不后台轮询，不改变scene。

后续自动调度采用唯一有界0.5秒任务，姓名板/目标变化立即失效，generation/target/context/逐字段版本全量匹配后才应用；旧回调不能覆盖即时查询。用户显式打开自动模式后，场景建议还须等待施法/引导/蓄力安全空闲，再撤销旧候选、无Token handoff和应用新规则。练习模式自动切换应暂停首步，不能自动把用户当前练习吞掉。

实机先验收友方/敌方/死亡、隐藏/显示、条目上限、Secret/NO_DATA与进出战斗。若仅有可见计数，可在UI中明确命名“按可见敌方单位切换”，不得承诺精确AoE命中判定。

## 动态优先级

Priority是纯消费器，按配置顺序选择一个精确ID；必要公共证据为目标存在、可攻击、存活，已学、范围、usable、资源不足=false、自身ready和GCD明确可派发，以及不移动、不读条、不引导。目标存在性不是有效敌对目标证明。未核验ID不进入候选。

当前ready/gcdClear无经过验收的适配来源，固定UNKNOWN，运行态不给Priority注入任何认证ready。因此所有动态结果无候选；模拟中构造的明确ready只验证选择逻辑，不算游戏能力结论。构筑/技能的移动或其他条件例外以后逐条建立明确规则，不能普遍忽略未知门槛。

下一步针对实际2136或用户选定的精确技能先建立必要依赖清单、有效来源、上下文与失效契约，再做对应状态适配。S61证明SUCCEEDED可能仍在读条；成功收据和存在性查询分离。取消、瞬发、急速变化不继承“正常完成后GCD已结束”的假设。禁止估算GCD、泛超时、静态CD、CDM活动补造ready。

## TEK兼容结论更新

初始草案关于“需要新的TEF技能目录”收窄：进一步核对SignalFrame.lua的ActionCode=0分支、engine.py和SafetyGate发现，现有TE本来允许未收录技能及饰品以ActionCode=0、真实BindingToken进入统一门禁，旧目录仅作为传输封套校验。TEK不以actionCode授权施法。

已用现有未修改TEK验证：TEF观察帧解码且拒绝输入；保留现有封套版本/指纹、ActionCode=0的1、SHIFT-1、CTRL-Q通过dry-run路径，action_id保持None。没有调用Windows发送器，不代表实机发送通过。

当前TEF观察帧目录为0、Token0、observation-only，默认关闭。未来真实帧可优先学习TE现有ActionCode=0路径，保留兼容封套而不冒认技能action_id。若实机TEK存在额外启动限制再做最小适配，现阶段TEK源码和用户配置均不修改。

绑定解析先限定明确支持的当前默认动作条精确技能，重验身份、槽位和BindingToken；宏兼容须按TE共享resolver的当前宏身份规则设计独立实现，不猜名称/图标或宏游标。支持范围明确展示，未验证来源不派发。

实际释放必须同时有TEF主动运行与输入许可、通过验证的状态/绑定、TEK启动许可、前台/Hook、手动让权、修饰键、freshness/replay/CRC及限频。成功只由游戏事件确认，TEK SendInput结果不是步骤收据。设置输入焦点无Token；脱战待命；施法/引导/蓄力无新派发。

用户确认TEF与TE不同时使用，因此当前不实施双源选择器。两者同时输出不受支持，不自动关闭另一插件或采第一条信号。若以后要求共存，另加来源隔离设计。

## 证据与测试边界

一手本机API定义：70338快照NamePlateDocumentation、SpellDocumentation、UnitDocumentation及FrameScript官方Secret检测。存在签名不证明战斗公开性。对应旁路分类在TEF有界诊断research字段保存，ready未知保留，不读取TEProbeDB。

模拟已覆盖两轮/重复轮、阈值滞回、未知撤回/过期、逐字段版本、整轮失效、目标存在不替代有效性、已学/范围/资源/自身ready/GCD/读条移动否决、配置代次和128条饱和。实机按MAJOR_UPDATE_TEST_0.2.0.md执行，未验收部分不开放输入。
