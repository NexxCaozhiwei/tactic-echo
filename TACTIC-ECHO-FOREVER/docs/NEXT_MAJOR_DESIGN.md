# TEF 大更新设计草案（待用户确认）

日期：2026-10-11。当前实现基线：0.1.3。本文件只提出设计，不表示已实现、部署或实机验收。

**确认后的实施更新：**用户选择手动切换、先双练习序列，同时开展自动/动态原型；TEF与TE不同时使用，TEK优先保持现状。多目标改为变形术→奥术飞弹。0.2.0第一阶段说明见README及AUTO_PRIORITY_AND_TEK_PLAN.md，下文保留原设计历史。后续核对发现TE/TEK已有ActionCode0兼容路径，原草案关于必须新增目录及双源选择器的建议不作为当前实施要求。

## 1. 产品定位与范围

TEF 继续作为独立无限服插件。学习 TE 的视觉结构、输入协议和工程分层，保持独立命名空间、TEF_DB、加载入口和状态生命周期，不调用 TE 内部函数，不读取 TE/TEProbe 数据库。

本次大更新由四部分组成：HUD、单体/多目标配置、设置中心、TEAP/TEK 适配。原固定顺序练习作为稳定模式保留。实时优先级推荐作为另一种明确模式，不能把练习提示包装成可立即施放的候选。

推荐的首次施工范围：新 HUD + 设置中心 + 手动单体/多目标两套练习序列 + TEAP 只读协议预演。真实 TEK 释放在必要状态和来源隔离验收后开启。自动敌人数与动态优先级按具体规则独立验收。

## 2. 数据与模块

链路：客户端安全读取 → 有版本的状态快照 → 场景选择 → 唯一推荐决策 → HUD呈现 / 派发门控 → 当前动作条绑定解析 → TEAP v3 → TEK既有门禁 → 单次SendInput。

游戏公开成功事件单独进入精确收据层。TEK按键发送成功不能推进练习步骤。成功推进后也不能强制清除读条/引导状态。

- SafeClient：逐字段官方Secret检测；外部调用、字段读取和不确定操作分别pcall；缺失或失败为UNKNOWN。
- StateStore：依照70338状态接口与消费契约保存来源、有效期和字段版本；迟到刷新不能覆盖更新的即时结果。
- SceneController：单体/多目标模式、配置代次；切换时撤销旧候选及输入资格。
- RecommendationEngine：唯一候选；支持练习序列，后续支持经过验收的优先规则。
- ReceiptTracker：继承当前精确ID、公开起始关联、成功墓碑与运行代次失效规则。
- HudModel / HudView：普通标量模型；客户端视觉对象仅用于渲染。
- DispatchGate / BindingResolver / TEAPEncoder：独立且唯一输入链路。

推荐显示与派发许可分开。练习技能可以在CD或状态未知时显示；此时输入Token为0。实时规则只有全部必要条件明确满足才产生可派发候选。

## 3. HUD

采用TE的主图标、次级只读卡片、常驻状态行结构，去掉与TEF目标无关的功能。

- 主卡：技能图标、名称、精确SpellID（可选）、可靠绑定、练习进度或实时规则原因。
- 预览：练习模式显示接下来两步；实时模式不宣称预测未来，默认只显示当前候选。
- 状态行：单体/多目标、手动/TEK、暂停/待命/运行、输入阻断原因。
- 控制：开始、暂停/继续、重置、打开设置；主卡仅作显示，控制按钮不直接施法。
- 外观：缩放、方向、间距、透明度、拖动与锁定、恢复位置；战斗内布局变更延后应用。
- 成功反馈仅由精确游戏成功事件触发，鼠标按下不冒充技能成功。
- 冷却视觉使用本客户端支持且已核验的官方接口；未知显示未知，不从静态时长或灰度制造秒数。视觉对象不参与推荐和输入资格。

HUD不显示“TEK已连接/已成功施法”，因为当前TEAP为单向信号；可以显示“协议输出开启”和插件侧阻断原因。真实发送结果由TEK侧诊断提供。

## 4. 单体与多目标

首版建议人工选择单体/多目标，可配置独立快捷键或HUD场景按钮。两种场景保存各自序列，精确ID与成功匹配列表独立；具体多目标技能不能从现有四步推导，施工时按角色已学技能和用户训练目标确认。

模式切换先输出无Token帧、增加配置/运行代次并撤销旧事件关联；练习模式回到所选配置第一步并暂停，用户主动开始。切换不允许旧施法成功消费新配置步骤。

未来自动场景需明确计数语义、公开数据来源、有界扫描、目标范围与失效规则。可见姓名板数量只能称为可见单位计数，不能称为技能实际命中人数。必要数据UNKNOWN时保持未知并等待人工选择，不擅自判单体。

实时优先规则需要列出每条规则的精确技能、必要条件、优先顺序和UNKNOWN行为。资源双布尔、范围或目标存在性只能作为各自条件，不能替代完整自身ready。动态模式下某条必要条件未知则不接纳该条；所有规则未满足时无候选。练习模式则保留当前步骤并说明状态。

## 5. TEAP与TEK

保持TEAP v3的20字节、CRC、Commit、Session、Sequence、Freshness、BindingToken及现有状态语义。TEF不得新增Windows输入通道、写按键、创建施法宏或修改目标。

现有SafetyGate检查目录版本和指纹；需设计TEF明确的目录/profile适配，不能借用无关职业目录身份。协议预演阶段输出observation-only和Token0。目录适配后才验证armed帧与真实绑定。

协议当前没有插件来源标识。默认自动定位不能证明找到的是TEF；双插件同开需要TEK显式来源选择和来源绑定的采样区域/布局校验，多候选歧义拒绝。不能在TEF中关闭TE，也不能自动采第一条信号。本项涉及TEK源码改动，需纳入施工授权；若用户只授权TEF，第一阶段仅支持用户手动确保单信号源的预演测试。

派发只复用可靠当前动作条绑定、验证过的宏身份和合法BindingToken。TEK保留前台、Hook、手动按键让权、修饰键、释放延迟、新鲜度、重放保护与限频门禁。未绑定、身份变化、Secret、UNKNOWN、未满足自身可用条件均Token0。

普通施法、引导、蓄力期间无新派发；脱战默认待命。用户打开设置编辑输入时撤销派发资格。reload、登录、暂停、重置、配置切换、来源切换均使旧候选和待处理工作失效，活动运行状态不落盘恢复。

奥术飞弹5143仍以成功开始引导完成练习步骤，但后续技能派发必须继续等待实际安全存在性查询确认引导结束；7268不推进。

左侧导航、右侧内容，面向TEF使用者命名，不暴露内部类名。

| 页面 | 内容 |
| --- | --- |
| 总览 | 当前版本/客户端、运行与输入状态、当前配置、开始/暂停/重置 |

## 7. 施工与验收顺序

1. HUD与设置、双场景练习：保留0.1.3事件回归，补场景切换、编辑应用、reload暂停、布局与图标失败测试。
2. TEAP只读预演：编码解码、CRC/Commit、目录、代次/新鲜度、布局来源隔离；所有输入为0。
3. 必要状态专项：按所选实际技能验证自身可用、GCD、目标/范围、移动、读条与引导；不靠模拟宣布实机ready。
4. TEK受控释放：明确授权后修改来源/profile适配；测试双源歧义、Hook、前台、真实按键让权、修饰键、绑定变更及一次SendInput。游戏成功事件单独核对。
5. 动态规则/自动场景：以具体配置及必要能力为单位验收，未通过项保持关闭。

完成各阶段的源码、模拟、必要TE/TEK回归、TOC、包结构与部署哈希检查。实机结果只按实际落盘证据报告，不把协议通过或进程存活当施法成功。
