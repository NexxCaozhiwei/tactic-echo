# TEF 0.6.0 连续派发首轮SOP

本版为固定序列实验，非动态优先级。新功能仅模拟验证；70338冷却/GCD可能Secret或61304无数据，导致持续等待，这是待实机确认的限制，不用模拟通过宣称游戏内可连续施放。

1. 保留TEF唯一信号源，桌面TEK使用UI联动。游戏/reload确认0.6.0；练习暂停、许可关闭、连续关闭。
2. 检查116、205、143精确等级默认动作条绑定；选择存活敌对目标、保持静止。关闭设置，关闭循环，重置，开启练习、TEK许可。
3. 点击HUD“开启连续”或/tef continuous。无需逐步点击派发。预期116→205→205→143，成功才计步；完成后连续关闭。
4. 若持续“连续等待”，执行/tef continuousstatus及/tef diag，记录固定原因。CONTINUOUS_COOLDOWN_UNKNOWN_OR_BLOCKED或CONTINUOUS_GCD_UNKNOWN_OR_BLOCKED表示公开数值证据不足，不代表TEK不兼容。不要反复点派发绕过本轮测试。/tef dispatch会停止连续并切回主动请求。
5. 再开始一轮，火球读条取消：不推进且连续停止。重新开启连续不重置当前步。插入顺序外成功技能应停止；失败也停止，不自动重试。
6. 多目标118→5143：5143成功开始引导计步，但下一循环必须等实际引导消失；7268不重复计步、不停止连续。可检查提前取消、暂停、重置、设置、许可与目标切换撤回。
7. 显式开启循环再测，相邻205必须两次独立成功；按/tef tekstop、/tef tekoff、/tef pause停止。正常/reload或退出落盘，回复“已落盘”，仅分析TEF自身数据及TEK自身trace。

公开数值采样每50ms在唯一协议心跳内进行，无估算GCD/施法时间；成功收据和施法存在性分开。连续不存储GUID、目标身份、原始受限值或API对象；诊断128条，重复等待原因不逐帧灌日志。TEK真实SendInput仍需另核对，不保证一请求仅一物理按键。
