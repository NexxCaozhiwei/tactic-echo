# TEF 0.14.3 加载修复与自定义APL条件

修正FrameXML.log确认的Bindings普通XML解析警告与重复分组头。Bindings.xml从TOC移除，但仍通过客户端约定的专用文件加载，保留6个命令与TEF自身override快捷键；不写技能绑定或SaveBindings。模拟检查同时约束TOC无此入口、安装包含文件和头唯一，客户端最终加载需reload实测。

自定义APL不再无条件要求ready=true，旧规则及新增规则requireReady默认false。关闭时不查询该冷却数值、不假写true，推荐是按条件排序的尝试，不承诺立即可施放。规则条件滚动区底部有“检查技能冷却数值（默认关闭；可能含GCD）”。显式开启才要求原公开0/0；未知仍阻断。已学、可用、资源足够与范围仍必需；用户选择的CDM/蓝量/距离等仍执行。派发即时复核使用同一配置，旧模板保留自身原ready条件。

## 5019次数与交接

固定序列5019*N按N次独立有效UNIT_SPELLCAST_SUCCEEDED计数，不按伤害命中或定时后摇；每次必须精确player/5019、公开成功身份、当前有效SENT或START关联，失败/重复/迟到不算。第N次成功立即切到下一步，下一业务帧尝试派发；不保证平台采样/客户端动作本身零延迟。APL规则不使用固定序列repeatCount，每次精确成功重新求值。

原通用CastIdle保护可能在射击成功后仍看到射击读条，因而等待它消失。本版仅对固定序列5019最后成功转到不同技能建立交接：普通施法查询必须公开确认spellID5019，所有引导查询必须确认无数据，且代次/索引/成功serial一致，才允许下一技能尝试。不是强行写读条不存在，不停止射击、不估算GCD；其他技能读条、引导、Secret/nil身份不豁免。新技能起始和生命周期失效清除交接，相邻5019仍按正常去重/活动保护。射击处于活动或未知时不再次按5019以免关闭自动射击。

用户体感额外等待的确切实机来源尚未闭合；S74只保存5019开战成功，没有固定N次完成至下一技能的有效链。本次优化只针对代码确认存在的射击读条阻挡，不能宣称已测到多余一整个GCD。

## 短实测

1. 停止派发，reload确认0.14.3，检查是否仍出现Bindings.xml警告；在设置确认F5保存并实测启停。
2. 自定义单体只启用143，移动/蓝量/距离/活动/CDM不限，冷却检查保持关闭。脱战观察10秒，然后手动143进战站定观察10秒。应不再出现custom:ready通用阻断；派发仍要求目标/范围/资源/绑定及战斗等门禁。
3. 再独立选择人工序列5019*2→143，装备魔杖并将两个精确技能放到真实绑定动作槽。测试模式按需选手动，主动开启，观察两次独立5019成功后是否切到143并尝试派发；5019活动时不应反复按键关闭，重复成功不多计。
4. 暂停、重置后不应复用旧射击交接。若仍等待，记录当前是射击、其他施法还是UNKNOWN；不靠动画推成功。停止派发，正常reload/退出落盘，回复“已落盘”，仅分析TEF自身数据。
