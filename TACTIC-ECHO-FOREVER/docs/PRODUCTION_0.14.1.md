# TEF 0.14.1 待命推荐

按用户要求，推荐显示不再要求已进入战斗。在APL来源且已主动开启意图的自动启停待命状态，自定义与旧模板都根据当前目标和自身公开状态评估规则，显示第一个合格技能。沿用既有0.5秒受限采样与事件失效，不新增轮询；手动停止仍停止运行，打开设置仍阻断派发，草稿未保存不参与推荐。

原本自定义Check与模板RuleAllowed把combat=true加入强制选择条件，造成脱战无候选；Trace.Waiting又只匹配combat:而漏custom:combat，错误显示“APL等待公开条件”。本版移除选择层强制combat，不假写combat=true。没有合格规则时，待命显示“APL待命：暂无满足条件的规则”，其它状态显示“APL暂无满足条件的规则”；具体原因在规则页与最近公开观察区。

预览仍要求已学、可用、资源足够、技能范围、自身冷却，以及用户配置的移动、蓝量、CDM、距离等条件。没有目标时攻击技能通常范围未知而没有候选；自身技能则可按明确self语义和自身条件显示，不要求凭空构造目标。距离不可读、蓝量Secret、CDM缺帧、自身CD未知仍不能授权对应规则；新增待命预览不保证所有配置总能推荐。

派发保持独立：自动启停模式脱战保持Runtime standby、Engine不运行、没有pending、TEAP状态paused、BindingToken0。APL Allowed入口/即时观察与最终Packet都要求当前公开combat=true。手动APL模式和开发Request同样不能借预览派发。战斗UNKNOWN可有只读候选，实际状态为blocked且零Token。进战事件使旧快照失效，重新评估、重核真实绑定与全部条件后才可派发；不把旧预览直接当ready授权。

预览本身不消费成功事件、不创建活动施法关联、不改变计数；成功推进仍由现有公开player/精确ID/当前关联SUCCEEDED。暂停、保存、切换来源、重置、reload仍按原生命周期失效。固定序列的既有尝试语义和TE/TEK源码未修改。

验证：291 Lua5.1模拟（194原功能+97APL），新增7项覆盖自定义待命预览/零Token、范围丢失恢复、自身技能无目标、移动优先级、蓝量变化、战斗UNKNOWN、手动APL不绕过；模板待命主卡显示与TEAP paused零Token也验证。包含进战后依赖失效不派发、恢复后原链正常派发、查询中途战斗false拒绝。新行为尚未游戏内验证。

## 短实测

1. `/tef tekoff`、`/tef pause`后`/reload`确认0.14.1。自定义单体暂保留实际已学火球术143一条；移动不限、距离不限、蓝量不限、CDM不限，保存并选APL。
2. 派发模式选“自动启停”，选择存活敌对目标，关闭设置，`/tef tekon`恢复许可后用HUD主动开启，保持脱战约10秒。条件公开合格时应显示火球术，状态仍“待命”，不能自动施放；条件未通过应显示暂无满足规则并给出范围/资源/自身CD等原因。
3. 清空目标5秒，应撤销攻击技能预览；恢复同一目标5秒应重新评估。不要把范围nil当作目标身份事实。
4. 可另设143“站定”、2136“移动中”两条，脱战移动/站定各5秒，观察候选或明确阻断原因。蓝量/CDM/距离条件可逐项恢复测试，UNKNOWN仍等待。
5. 手动攻击进战，观察是否重新核对当前规则并派发；退出战斗后应回待命，预览可继续更新，派发停止。
6. 手动停止后不应因进战或预览复活意图；正常reload/退出落盘，回复“已落盘”。仅分析TEF_DB，不借其他数据库证明结果。
