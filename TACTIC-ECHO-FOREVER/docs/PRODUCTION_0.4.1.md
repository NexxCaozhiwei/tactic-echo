# TEF 0.4.1 生产使用与短实测

1. 仅启用TEF信号源，停用TE插件。桌面TEK选择“UI联动”，不要同时运行验收脚本或另一个派发器。游戏保持前台；切到终端/Codex时TEK应等待前台。
2. `/reload`，确认0.4.1。将当前练习精确ID的技能直接放到默认动作栏，并在游戏按键设置中绑定TEK支持的键（例如1、2、3或SHIFT-1）。116与205不是自动等价；宏暂不支持。HUD键位未解析时先核对技能等级与槽位。
3. 先选好目标；点“开启练习”，再开“TEK许可”。关闭设置。点HUD“派发当前”，或按游戏原生按键设置→TACTIC-ECHO-FOREVER→“派发当前技能”的快捷键。也可 `/tef dispatch`。请求快捷键若触发TEK手动让权，先释放键并等待既有门禁，勿取消手动优先策略。
4. 每步主动请求，观察116→205→205→143逐步成功推进。请求会在对应SENT/START/失败等事件时撤回，下一步不自动请求。若技能CD、目标不合适或施放失败，保持当前步骤，修正条件后再次请求。桌面UI联动按现有限频工作，事件到达前可能重复发键，不保证一个请求仅一次输入。
5. 火球术读条取消不能计步；插入顺序外技能不能跳步。多目标练习118→5143：奥术飞弹成功开始引导即可推进，7268子事件不多推进，提前取消可能已经计步。测试暂停、继续、重置首步暂停、完成停止及循环仅回首步不自动请求。
6. 请求期间无关动作槽更新应保留；锁定槽换技能/键位/按钮、来源未知、开设置、换目标或进战应撤回。重新确认条件后主动请求。HUD CD与充能纯展示，不构成施放可用证明。
7. 停止用原生“停止练习及TEK请求”快捷键，或 `/tef tekoff` 后 `/tef pause`；同时停止桌面TEK UI联动。正常 `/reload` 或退出落盘。再说“已落盘”，读取TEF自身SavedVariables与TEK自身trace核对请求/撤回、input_sent和精确成功计步；TEF日志本身不能证明Windows已发送。

本版本已完成模拟及部署校验，新版本真实屏幕定位、Hook、SendInput、HUD外观和游戏结果尚待上述实机验证。插件没有TEK双向确认，因此显示“派发请求”不等于“TEK已连接/已发送”。
