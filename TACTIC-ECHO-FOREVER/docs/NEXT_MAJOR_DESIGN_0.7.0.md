# TEF 0.7.0 大改设计（待用户确认后施工）

遵循用户此前“大更新先设计、确认后施工”的要求。本文件记录2026-10-11新增需求，不修改当前运行代码。

## 独立推荐与共享派发

TEF没有WoW官方推荐。推荐源接口统一返回当前技能、精确匹配ID、来源、配置版本及步骤身份。首版接人工固定序列与代码定义序列，后续APL实现同一接口。推荐源不持有TEK权限，不调用TE函数，不直接生成输入。

流水线：职业/专精/场景配置 → 推荐源 → 统一派发控制器 → 当前动作栏精确绑定 → TEAP v3 → TEK门禁 → SendInput → 游戏成功收据。

固定练习是明确授权的输入尝试，不要求官方推荐存在，不把未知CD/GCD解释为ready。未来动态/APL按各规则明确的依赖验收，不能把固定尝试授权扩展成任意动态候选资格。成功仍只认当前步骤精确SUCCEEDED；5143开始引导语义保持。

TEAP尽量保留v3线格式。推荐来源在插件及TEK非线诊断中标为TEF人工序列/代码序列/APL；不为改名另造TEFAP。TEK保留真实绑定、前台、Hook、手动优先、新鲜度、重放及限频。只有确认TEF业务需求被某个生产条件错误阻塞时才针对性适配。手动按键等待不能当错误关闭；需要明确展示状态。

## 职业与专精隔离

配置以职业英文token/专精标识/单体或多目标分层；无专精的低等级角色使用职业基础配置键。职业未知时待命，不回退到法师。法师旧single/multi数据只迁移到法师配置；其他职业初始为空并提示“未配置推荐序列”，不猜技能ID或扫描全法术目录。

界面只编辑当前职业/专精配置，可切单体/多目标；代码配置文件可提供已明确核对的职业序列。角色/专精变更使旧请求和关联失效。APL留出模块接口，本轮不把全职业APL作为交付目标。

## 统一派发启停及三种模式

TEAP信号、TEK请求许可默认打开；它们属于高级总闸，不等同正在输入。HUD、设置和自定义快捷键共用一个“派发启/停”意图入口，显示运行、待命、暂停、文本输入让权、等待收据、失败停止及未配置。旧“练习开启+许可开启+连续开启”步骤合并。

默认建议采用TE的自动启停模式：

|模式|启用及进战|脱战|登录/reload|
|---|---|---|---|
|自动启停|启用后待命，进战运行|待命，零Token|可按自动启动偏好进入新的待命会话|
|手动启停|按键或按钮启用；可脱战练习|保持用户运行意图|自动启动偏好关闭时暂停|
|脱战后停止|手动启用|停止，后续进战不自行恢复|按模式进入停止状态|

独立“自动启动”偏好控制是否在新会话自动建立启用意图；不恢复旧pending、GUID、运行代次或成功关联，新会话从首步重新校验。手动暂停必须覆盖自动模式，不能被下一次战斗事件自行解除。没有合法职业配置、绑定、目标或公开必要状态时，即使默认许可打开也输出零Token。

单步派发移至测试工具；自动运行期间该入口不得隐式关闭运行状态或重置pending。重复启动和重复请求对当前身份幂等，不能每次Cancel再新建。完成非循环序列停止；显式循环按新成功收据继续。

失败/中断不计步。首版保持停止或显式重试，是否加入自动重试后续独立设计；不能为了“连起来”制造无限连发或超时成功。

## 自定义快捷键与设置

参考TE ControlPanel录入、应用、清除与脱战延迟应用机制。用户此次明确授权TEF派发控制快捷键；仅设置插件启停动作的临时override，不改动作条技能绑定、宏或全局SaveBindings，不创建施法按钮或第二输入通道。使用独立TEF名称和SavedVariables配置。冲突提示，不静默抢技能键；战斗内修改保存草稿、脱战应用，旧控制仍可停止。

设置首页集中：派发启停、运行模式、自动启动、快捷键、当前职业/专精/场景与推荐源。许可/协议开关保留高级设置；旧测试面板保留。HUD按钮、热键与设置显示同一状态，不把推荐或CD显示当输入授权。

## 验收与交付

必须模拟验证：职业隔离/法师迁移/未知职业、推荐源与运行解耦、三模式进脱战和手动暂停、登录自动启动不恢复旧任务、重复点击幂等、热键冲突/脱战延迟、相邻205与5143/7268、失败和迟到收据、手动让权、128条有界日志。日志增加公开业务采样序号、请求序号及固定状态转换原因，不保存GUID、目标身份或Secret原值。

实际验收第一轮只用法师116→205→205→143：单一派发开关启动后不再逐步点按钮，核对连续请求、TEK真实输入和游戏四条成功分别成立。再换其他职业确认没有法师推荐，再测试三模式和快捷键。代码、文档、基线、打包及独立目录哈希部署保持现有约定。
