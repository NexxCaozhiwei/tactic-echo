# TEF 0.6.1 连续固定练习

0.6.0的S34实测没有连续请求，主要被强制零GCD/零技能冷却数值挡住，并被无关动作栏刷新停止。手动请求仍完成116→205→205→143。0.6.1学习TE普通推荐传输语义，将用户指定序列作为固定输入尝试，不宣称其ready，也不把UNKNOWN当ready。动态优先级及自身ready判定仍未闭合。

## 首轮实测

1. /reload确认0.6.1；默认暂停、许可关闭、连续关闭。保持TEF唯一信号源，桌面TEK使用UI联动。
2. 先选择存活敌对目标并确认116/205/143精确动作栏绑定。关闭设置、停止聊天输入，保持静止。关闭循环，重置，开启练习及TEK许可。
3. 只点击一次HUD“开启连续”，之后不点击“派发”。预期116→205→205→143，游戏成功才推进；相邻205要两个独立成功。进入战斗不应使连续关闭，无关动作栏刷新不应停止。
4. 若等待，使用/tef continuousstatus查看固定原因，再/tef diag。连续模式不读取自身CD、61304或充能作为输入门槛；实际读条/引导存在、公开目标/范围/usable不满足、移动或文本焦点未知仍不派发。请求发出后等待游戏收据，不因超时重试。
5. 取消火球应不推进并停止连续；重新开启维持当前步。切换目标、设置、暂停、重置、关闭许可都停止。文本编辑期间禁止派发；请求期间出现焦点将撤回并停止。
6. 多目标118→5143，5143成功开始引导就计步，7268不重复；下一循环实际引导仍在时不得请求。默认不循环完成后停止，显式开启循环再检查回首步。
7. /tef tekstop、/tef tekoff、/tef pause停止，正常reload或退出落盘，回复“已落盘”。仅用TEF自身收据核对游戏步骤，TEK自身trace另核对Windows输入。

输入尝试可能因GCD、自身CD或其它条件失败；失败/中断停止，不会重试或跳步。不读取或恢复其它插件数据库，不改目标/宏/CVar/按键，不增加输入通道。TEK仍有全部前台、Hook、手动优先、新鲜度、重放及限频门禁；游戏事件撤回前可能多次按键。

新修复仅模拟验证；不能用S34手动成功当连续派发成功。
