# Tactic Echo 1.4.13 基线

`1.4.13` 将可选技能注入的通用公开可用性从“步骤释放证据”收口为“当前派发闸门”，解决移动中的读条/持续施法技能被连续失败熔断移出注入链的问题。

## 临时不可用闸门

- 仅对已验证动作栏来源且已有真实 BindingToken 的可选 spell 注入读取公开 `GetSpellUsability()` 与 `GetActionUsability()` 布尔值。
- 两个探针必须在同一共享 RuntimeSnapshot 中读取；实际动作槽的明确布尔值优先决定 TEK 将按下的来源当前是否可用，技能探针继续提供精确资源不足证据。
- `usable=false` 且没有明确资源不足、普通施法/GCD 延后或自身 CD 时，步骤标记为 `TEMPORARILY_UNUSABLE`。预检必须保留该步骤，运行期只输出 observation-only hold 与 `BindingToken=0`。
- 下一新鲜快照恢复可用后，原 plan、group、stepIndex 和顺序继续执行；不得重建组、越过步骤或直接绕过 GCDGate 派发。

## 失败与恢复

- 当前尝试收到匹配失败后若观察到临时不可用，该失败不得参与两次失败释放证书，并且同一尝试只撤销一次。
- 临时不可用期间不得消费新的派发尝试或重复发布 Token；恢复后仍须完成既有 observation-only 失败隔离，并在公开 `READY_NOW` 建立新的逻辑尝试。
- 明确自身非 GCD 冷却优先于通用不可用，避免冷却中的按钮形成永久 `wait_usable`。
- 绑定/宏/装备身份失效、稳定资源不足、真实自身 CD、脱战、死亡、切图和其他既有硬终止边界保持不变。

## 不变边界

- 不读取玩家速度，不维护移动技能白名单，不依赖本地化错误文本，也不新增事件、OnUpdate、轮询器或并行状态机。
- 步骤仍只由精确成功事件、稳定自身非 GCD 冷却开始或真实多充能减少确认。
- BindingToken、TEAP v3 20 字节、TEK 前台/Hook/手动让权/新鲜度/限频门禁、脱战硬门控和唯一活动组所有权均未放宽。
