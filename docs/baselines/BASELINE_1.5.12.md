# Tactic Echo 1.5.12 基线

继承 1.5.11，修复高亮资源消耗技能因可用性不足而持续抢占官方推荐的问题。

- 高亮候选必须先有客户端明确高亮、当前动作条 resolver 验证的真实 BindingToken、自身冷却/充能可用及 `READY_NOW` 或 `QUEUE_WINDOW` GCD 时序，再对精确 SpellID 调用共享 `RuntimeSnapshot:GetSpellUsability()`。
- 只有公开布尔 `usable=true` 且无明确资源不足冲突才允许高亮优先派发。`usable=false` 且 `notEnoughResource=true` 记录资源不足；其他明确不可用或 UNKNOWN 都不能抢占官方推荐。
- 一个候选不合格时按原动作条顺序检查下一个高亮候选；全部不合格时同帧回到官方推荐及其现有特殊模式路径，不等待资源积累。
- 仅导出资源不足、不可用和未知的候选数量与原因；不得读取、保存或导出具体资源数值。宏仍使用共享 resolver 的当前来源与正文验证；可用性探针不替代宏身份验证。
- AutoBurst 仍只根据不可变官方推荐选择窗口；有效 plan/capture 保持优先。TEAP v3、BindingToken、TEK 门禁、手动优先及脱战门控保持不变。

## 验收范围

- 资源不足的首个高亮技能不会阻止后续明确可用的高亮技能。
- 所有高亮候选资源不足、普通不可用或可用性未知时，官方推荐继续派发。
- 实测目标客户端对“最终审判”“神圣风暴”的可用性返回形态，确认资源不足时不再出现等待平A积累资源而持续压制官方推荐。
