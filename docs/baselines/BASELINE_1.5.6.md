# Tactic Echo 1.5.6 基线

继承 1.5.5 的 HUD 与 1.5.4 的自动注入执行基线，修复复合宏的按钮状态被误当成当前步骤状态。

- 多行 `/cast`、`/use 13` 与 `/castsequence reset=2` 继续由共享正文语义匹配和当前动作条身份校验提供真实 BindingToken，不改写玩家宏，也不执行或推测宏分支。
- 新增共享 `IsSpellActionStateTrusted`：只有正文所有技能动作均关联当前请求技能、且不含饰品槽位和 castsequence 的宏，才能以按钮状态辅助该技能采样。直接技能路径不变。
- 多技能/序列宏仍允许 TEK 经既有路径派发；自身冷却与资源可用性改用当前精确 SpellID，避免另一技能的 GCD 覆盖自身 CD，或另一技能的资源不足导致当前注入被跳过/卡住。
- 精确技能成功收据继续仅确认当前 WAIT_CONFIRM 步骤；序列中的另一技能成功不得推进游标，不新增序列模拟器、输入通道或轮询。
- 通用 `/use 13` 已有兼容不变；增加有效宏索引、opaque handle 加唯一宏名正文恢复、装备身份不符及空槽回归。`#showtooltips` 被当作注释忽略，不作为身份依据。没有运行日志证明用户所见饰品问题来自哪一 API 形态，不能以这些离线测试宣称该现象已实机修复。
- 多技能宏的目标步骤仍须明确自身可用，UNKNOWN 不会因为宏按钮可用被首次派发。双饰品宏、正文不可读/身份歧义和装备变更继续关闭派发。

本地验证：pytest 753 passed、7 skipped、17 subtests passed；TEK unittest 227 项与 AddOn unittest 243 项通过；52 个 Lua 文件语法、compileall 和基线契约通过。客户端宏实际执行顺序与冷却读取仍需实机验收。
