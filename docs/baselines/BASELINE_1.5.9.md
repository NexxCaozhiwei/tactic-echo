# Tactic Echo 1.5.9 基线

继承 1.5.8，新增高亮推荐候选派发。

- 设置中心新增“高亮推荐”页面。全局总开关默认关闭；逐专精保存技能停用表；启用后已解析动作条技能默认参与候选优先级。
- 候选来源为当前动作条 resolver 缓存，按动作条显示顺序最多采样 36 个不同 SpellID。宏候选只在共享 resolver 验证当前动作来源和正文语义后参与；未知、歧义或 opaque 宏身份不授权。
- 只接受 `C_SpellActivationOverlay.IsSpellOverlayed` 或兼容 API 返回的公开布尔 `true`。每次派发仍须有真实 BindingToken、自身冷却/充能可用证据，以及 `READY_NOW` 或 `QUEUE_WINDOW` GCD 时序；每帧只选择一个技能。
- 高亮状态未知、无高亮、命中技能被停用、绑定/冷却/GCD 不合格时，回到未变更的官方推荐链路。停用技能仍可作为官方推荐正常派发。
- `OfficialRecommendation` 原始结果仍是 AutoInjectionCoordinator 的唯一输入。自动注入计划、capture、窗口所有权、组忽略与派发顺序保持既有语义。
- 特殊模式只替换官方推荐来源，不替换高亮来源，不改变官方推荐快照，不递归应用。
- 手动动作条/HUD 优先、输入焦点、暂停、施法/引导/蓄力、脱战门控及 TEAP v3 / TEK 安全门禁保持优先；不创建输入路径、不增加 TEAP 协议位。消息仅加诊断用 `recommendationSource` 标量。
- 高亮状态未知按“无高亮候选”处理并使用官方推荐，避免新功能影响原官方路径。设置总开关默认关闭。

## 验收范围

需要验证总开关开/关、每技能停用、无高亮回退、多高亮动作条顺序、API 缺失/Secret/错误回退、技能自身冷却/GCD等待、绑定变化、宏身份失效、特殊模式只作用于官方来源、自动注入窗口仍匹配官方 SpellID，以及手动优先和脱战门控。离线验证不能替代目标 Retail build 的高亮 API 与派发实机验证。
