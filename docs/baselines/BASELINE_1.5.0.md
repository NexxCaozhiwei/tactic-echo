# Tactic Echo 1.5.0 基线

`1.5.0` 是自动注入稳定性与 HUD 信息收口里程碑：定版单次锁链、单向游标、后续冷却候补、移动失败等待，以及暴雪原生技能/物品提示。

## 单次锁链与单向游标

- 官方窗口命中时只建立一个 OrderedPlan；完整配置顺序为唯一顺序权威，每步冻结原始 `configuredIndex`。
- 初始可用、临时不可用或资源待确认步骤进入活动链；明确自身 CD 且绑定/装备身份有效的可选步骤进入候补。
- 候补只能在配置游标尚未越过时按原位置补入；已经越过的步骤永久过期，不得回填、重建计划或重放前缀。
- 所有运行时复检复用唯一 AutoInjectionCoordinator、唯一 AutoBurst OrderedPlan 和既有 SignalFrame 业务刷新。

## 锁定步骤与移动等待

- 可选步骤一旦进入活动链，匹配失败事件只建立无 Token 隔离并重试同一步，不再按失败次数删除。
- 匹配失败时若玩家正在移动，步骤进入 `burst_step_wait_movement`；移动期间不发布 BindingToken，停下后再经过既有隔离恢复派发。
- 窗口步骤仍保留两个精确失败的有界释放；明确自身 CD、绑定/宏/装备变化、稳定资源不足、脱战、死亡和切图仍是硬边界。
- 步骤成功只接受精确成功事件、稳定自身非 GCD 冷却开始或真实充能减少。

## HUD 原生提示

- 技能卡按安全普通值 SpellID 调用暴雪 `GameTooltip:SetSpellByID()`。
- 装备饰品优先按角色装备槽调用 `GameTooltip:SetInventoryItem()`；其他物品按 ItemID 调用原生物品提示，并保留原生链接兼容回退。
- HUD 不再追加类型、状态、原因、绑定、CD 来源、转盘模式、注入组、队列位置、视觉效果或手动点击状态等内部字段。
- 原生提示无法建立时只显示安全名称，不恢复诊断明细。

## 不变安全边界

- AutoBurst 不是第二条输入通道；所有自动派发继续经过已验证动作条、BindingToken、TEAP v3 与 TEK 全部门禁。
- 任何脱战帧不得创建或保留 Burst plan/capture，不得产生 Burst candidate。
- HUD、Tooltip、冷却转盘和诊断仅属于视觉/审计层，不得改变推荐、候选、派发资格或步骤确认。
- HUD 手动点击继续只复用既有安全动作条代理；战斗保护、手动让权和输入优先级保持不变。
