# Tactic Echo 1.4.14 基线

`1.4.14` 将自动注入计划收口为“单次锁链、单向游标、后续候补补入”：窗口命中时只建立一次计划，执行过程中不重建或重放已走过的链前缀。

## 初始锁链与候补

- 完整配置顺序是唯一顺序权威；每个步骤在预检时冻结原始 `configuredIndex`。
- 初始可用、临时不可用或资源待确认步骤进入活动链；明确自身 CD、但绑定与装备身份仍有效的可选步骤进入冷却候补。
- 所有可选步骤均不可进入活动链时仍不创建计划；focused 模式的既有全量预检边界保持不变。
- 计划继续共享唯一 AutoInjectionCoordinator、唯一 AutoBurst OrderedPlan 和唯一活动候选。

## 单向补入

- 当前活动步骤的原始配置序号构成只向前移动的游标。
- 候补序号小于或等于当前游标时永久过期；后续即使恢复，也不得回填或触发计划重建。
- 候补序号位于游标之后时持续通过现有 RuntimeSnapshot、绑定、冷却和 GCD 采样复检；恢复后插入活动链的原始相对位置。
- 最后一个活动步骤确认完成即关闭计划；未及时恢复的剩余候补不进入本轮。

示例：

- `A→W→B→C` 中 C 初始 CD，活动链锁定为 `A→W→B`；C 在 B 确认前恢复后追加为 `A→W→B→C`。
- A、C 初始 CD 且 B 可用，活动链锁定为 `W→B`；A、C 后续同时恢复时 A 已在游标之后方，只有 C 可追加，最终为 `W→B→C`。

## 已锁定步骤与失败

- 可选步骤一旦进入活动链，匹配 `UNIT_SPELLCAST_FAILED`、`UNIT_SPELLCAST_FAILED_QUIET` 或 `UNIT_SPELLCAST_INTERRUPTED` 不再构成删除证书。
- 每次匹配失败仍必须经过现有两帧 observation-only 重试隔离，之后只重试当前步骤；不得越过或从链首重放。
- 失败发生时若 `GetUnitSpeed("player")` 明确显示玩家正在移动，步骤进入 `burst_step_wait_movement`；移动期间不得发布 BindingToken，停下后才恢复隔离与重试。
- 窗口步骤仍允许两个精确匹配失败形成有界释放；明确自身 CD、绑定/宏/装备身份变化、稳定资源不足、脱战、死亡和切图等硬边界保持优先。

## 不变边界

- 步骤成功仍只接受精确成功事件、稳定自身非 GCD 冷却开始或真实充能减少。
- 候补复检复用活动 plan 的既有 SignalFrame 业务刷新，不新增事件、OnUpdate、定时器或并行状态机。
- BindingToken、TEAP v3、TEK 前台/Hook/手动让权/新鲜度/限频门禁、脱战硬门控和唯一组所有权均未放宽。
