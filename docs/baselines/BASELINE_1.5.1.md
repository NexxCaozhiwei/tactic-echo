# Tactic Echo 1.5.1 基线

`1.5.1` 收紧自动注入的首次派发资格，同时保留已正确接纳步骤的持续派发：先以明确自身可用证据准入，再由唯一单向游标执行；施法过程不改变计划，移动不再长期停派。

## 正向可用准入

- 每个技能或饰品首次发布 BindingToken 前，必须通过当前可信动作条绑定、装备身份以及实时冷却/充能采样，并明确得到自身可用状态。
- `UNKNOWN`、opaque 冷却、明确自身非 GCD 冷却以及无可用充能都不得借 `READY_NOW`、`QUEUE_WINDOW` 或 `GCD_LOCKED` 降级成候选。
- 明确自身 CD 但身份有效的未来步骤可留在候补；只有在游标越过前重新取得明确可用证据时，才可按原配置位置加入。
- 当前步骤明确观察到自身 CD 后立即停止重派；稳定的不同业务样本仍用于成功确认或 simple 跳过，不以 GCD 代替自身 CD 证据。

## 接纳后持续派发

- 首次以明确 `OWN_READY` 进入 `WAIT_CONFIRM` 的步骤记录正向准入状态。
- 同一步骤等待确认期间若冷却读数短暂变为 UNKNOWN，可继续使用公开 GCD 阶段和共享 TEK 限频派发；该兼容不能授权任何新步骤首次派发。
- 精确成功事件、稳定自身非 GCD 冷却开始或充能减少仍是成功确认；失败事件不构成成功或跳过。
- 可选步骤匹配失败后只经过既有两帧无 Token 隔离，再继续当前步骤；不会因失败次数从活动链删除。

## 施法保护与移动语义

- 普通施法、引导和蓄力在规则选择、规则变化处理、capture 恢复、候补扫描和步骤采样之前进入 observation-only 暂停。
- 暂停期间保持唯一 plan、group、stepIndex、WAIT_CONFIRM 与候补集合，不创建新候选，也不让后续步骤越过当前施法。
- 移动时动作槽 `usable=false/notEnoughResource=false` 只作诊断，不否决已经由明确自身可用证据建立的派发资格。
- 移动失败不再建立持续等待；诊断保留 `failureObservedMoving`，但 `movementRetryHold` 恒为 false。

## 单向配置游标

- 配置中的 `configuredIndex` 是唯一顺序权威；活动计划不重建、不重放已完成前缀。
- 未来 CD/UNKNOWN 候补可在当前步骤完成前恢复并加入；位于当前游标或其之前的候补永久过期。
- 窗口之后的未来候补允许计划先执行明确可用的窗口；到达其配置位置时仍未明确可用则自然越过，不在稍后回插。

## 不变安全边界

- 自动注入继续只有唯一 AutoInjectionCoordinator、唯一 AutoBurst OrderedPlan、唯一候选，并沿用 BindingToken → TEAP v3 → TEK → 单次 SendInput。
- 脱战、死亡、载具、切图、绑定/宏/装备身份变化仍按既有 fail-closed 门禁处理。
- HUD 冷却、原生 DurationObject、Tooltip 和诊断不参与派发资格、步骤跳过或成功确认。
- 新增诊断仅包含安全标量，不导出宏正文、原始受保护冷却值或用户敏感数据。
